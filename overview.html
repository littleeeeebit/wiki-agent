AI 코딩 에이전트는 세션이 끝나면 배운 것을 잊습니다. 이 저장소는 교훈을 적어 두고, 필요한 순간에 에이전트 눈앞에 먼저 펼쳐 줍니다.

프로젝트 A · 월요일리뷰를 엉뚱한 셀에 보냄세션 종료 — 기억 사라짐
프로젝트 B · 수요일리뷰를 엉뚱한 셀에 보냄세션 종료 — 기억 사라짐
프로젝트 A · 금요일리뷰를 엉뚱한 셀에 보냄…

문서로 남겨도 소용없었습니다. 문서는 안 읽히면 그만이니까요. 부족한 건 저장 공간도 검색도 아니었습니다. 그래서 이 위키가 하는 일은 딱 둘입니다. 반복되는 지시는 스킬로 굳히고, 검사로 바꿀 수 있는 규칙은 검사로 바꿉니다. 판단이 필요한 나머지는 글로 둡니다. 판단할 일을 기계로 막으면 헛경보가 작업을 멈추기 때문입니다.

project그 저장소만의 규칙각 프로젝트의 .wiki/에 둡니다. 남의 지뢰가 섞여 들어오는 것 자체가 사고라서.

손으로 쓴 규칙 페이지는 몇 장뿐입니다. 나머지 문서는 세션 시작 때 목록만 한 번 넣어 주고, 본문은 에이전트가 필요할 때 엽니다. 규칙이 실패하는 방식은 “안 읽었다”라서 훅이 밀어 넣고, 문서가 실패하는 방식은 “있는 줄 몰랐다”라서 목록이면 충분합니다.

세션 하나에서 일어나는 일

훅이 끼어드는 세 순간

SessionStart세션을 열 때
  • 현재 브랜치와 작업트리 상태
  • 하다 만 계획의 남은 단계
  • 최근 결정과 그 이유
  • 모든 문서의 목록
UserPromptSubmit말을 걸 때마다
  • 말에 걸린 규칙 페이지
  • 한국어 말의 영어 번역
  • 매번 붙는 짧은 계약 몇 개
PreToolUse도구를 쓰기 직전
  • 계산해야 보이는 위반만 검사
  • 예: 진행 설명에 한글이 남았나, 파일을 통째로 되쓰나

“뭘 하던 중이었지”는 어떤 말에도 걸리지 않으니, 세션 시작 때 따로 한 번 넣습니다. 그리고 훅은 고장 나도 막지 않습니다. 번역 키가 없거나 스크립트가 터져도 작업은 그대로 갑니다. 일을 멈추는 강제는 결국 사람이 꺼 버리기 때문입니다.

두 언어

왜 에이전트는 영어로 쓰고, 사람은 한국어로 읽나

한때 위키 페이지, 훅 프롬프트, 진행 보고가 전부 한국어였습니다. 그러자 에이전트가 한국어로 생각하고 쓰는 동안 눈에 띄게 덜 정확해졌습니다. 훅과 위키 양쪽에서 같은 현상이 관찰됐습니다. 한 언어로 생각하고 다른 언어로 쓰는 비용을 매 턴 내고 있었던 겁니다.

그래서 나눴습니다. 에이전트가 닿는 모든 표면은 영어(문서·프롬프트·진행 보고·코드 주석)로 쓰고, 그 위에 Gemini 번역을 한 겹 덮어 사람은 여전히 한국어로 쓰고 한국어로 읽습니다. 두 언어는 타협이 아니라 두 독자입니다.

사람이 보는 쪽 · 한국어 “PR #91 리뷰 루프 돌려” 리뷰 셀에 라운드 3을 보냈습니다.
ko → en입력en → ko출력
에이전트가 보는 쪽 · 영어 Run the review loop on PR #91. Sent round 3 to the review cell.
어디서방향무엇이
사용자 입력ko → eninject.py가 한국어 말 아래에 영어 번역을 붙입니다. 한국어 원문이 늘 기준입니다
세션 시작 정보ko → ensession_state.py가 커밋·결정 기록을 영어로 옮겨 넣습니다
터미널 출력en → komirror.py가 에이전트의 영어 설명을 옆 화면에 한국어로 띄웁니다
웹 채팅양방향대화 화면에서 영어 답변 위에 한국어 오버레이를 켜고 끕니다
순서의 규칙은 하나였습니다. 한국어로 읽을 길이 서기 전에는 사람의 화면을 영어로 바꾸지 않는다.

그래서 미러부터 만들었고, Claude와 Codex 각각에서 한국어가 제대로 뜨는 걸 확인한 뒤에야 “진행 설명은 영어로” 규칙을 켰습니다. 반대 순서였다면 사람은 돌아갈 길 없이 영어만 보고 있었을 겁니다.

끝까지 한국어로 남는 것
  • 규칙의 triggers 정규식사용자 말을 매칭합니다. 말은 한국어라, 영어로 바꾸면 주입이 통째로 죽습니다
  • 커밋 · PR · 결정 기록사람이 GitHub에서 읽습니다. 에이전트에게 넘길 때만 번역합니다
  • 거절 문구 · 질문 선택지 · 상태 메시지사람이 읽는 화면이라서
  • 용어집의 법령 용어 · 고유명사번역하면 다른 것을 가리키게 됩니다
번역기의 약속 · tool/translate/
뜻이 새지 않게명령·경로·링크·용어집 단어는 번역 전에 빼 두었다가 다시 끼웁니다. 하나라도 어긋나게 돌아오면 번역을 버립니다
실패해도 원문키가 없거나 시간을 넘기면 원문을 그대로 씁니다. 번역 실패는 번역만 잃습니다
빠르게매 발화마다 돌기에 가벼운 모델(gemini-3.1-flash-lite, 왕복 약 1초)로 고정했습니다
한 번만같은 문장은 캐시가 먼저 답합니다. 요청도 키도 필요 없습니다
요금 분리키는 기계 전역이 아니라 저장소 옆 .env에 둡니다. 다른 프로그램과 요금이 섞이지 않습니다

A · 규칙 연결

내 프로젝트에 공통 규칙 붙이기

Python 3.11+GitClaude Code 또는 Codex CLIWindows: Git Bash · PowerShell
  1. 훅이 쓰는 패키지 설치 
    python -m pip install -r requirements-hooks.txt
  2. 대상 프로젝트에 .wiki/adapter.toml 만들기

    그 프로젝트의 실제 검사 명령으로 채웁니다. adapters/example.toml은 가짜 예시입니다.

    agents = ["claude", "codex"]

[slots]
review_dir   = "artifacts/review"
gate_cmd     = "python -m pytest"
live_cmd     = "confirm the real events in a new session"
server_stop  = "Ctrl+C in the terminal that started it"
scratch_dirs = "artifacts/"
  3. 위키 버전 고정

    위키 폴더에서 git rev-parse HEAD를 실행하고, 나온 40자를 대상 프로젝트의 .wiki/wiki-revision에 한 줄로 저장합니다(UTF-8, BOM 없음, LF).

  4. Codex를 쓴다면 훅 켜기

    대상 프로젝트의 .codex/config.toml에 추가합니다. 파일이 있으면 덮지 말고 이 항목만 더합니다.

    [features]
hooks = true
  5. 설치하고 확인

    위키 폴더에서 실행합니다. 하나만 쓰면 --agent claude 또는 --agent codex.

    python tool/setup_agents.py --project "../내-프로젝트" --agent both
python tool/setup_agents.py --project "../내-프로젝트" --agent both --check  # 읽기만
  6. 새 세션에서 실제로 확인

    --check 통과는 배선 확인일 뿐입니다. 새 세션을 열어 프로젝트와 훅을 직접 신뢰한 뒤, 세션 시작 정보가 오는지, 규칙을 묻는 말에 그 규칙이 붙는지 봅니다.

프로젝트나 위키를 옮겼다면 같은 명령으로 다시 설치합니다. 위키 버전을 올릴 때는 변경을 검토하고 wiki-revision을 새 값으로 바꾼 뒤 재설치합니다.

B · 위키 채팅

브라우저에서 위키에게 묻기

Python 3.11+Node.js 22.12+Git본인 계정의 CLI
  1. 설치와 내 계정 로그인

    쓸 CLI에 맞춰 하나만 실행합니다. 패키지와 화면을 준비하고, 로그인이 안 돼 있으면 공식 로그인 창을 엽니다.

    python tool/setup_chat.py install --agent claude   # 또는 codex, both
  2. 지도 파일 만들기

    처음 한 번, 그리고 규칙을 고친 뒤마다.

    .venv/Scripts/python tool/graph.py   # macOS·Linux: .venv/bin/python
  3. 실행 
    .\tool\chat.cmd        # Windows
tool/chat.command      # macOS·Linux

    브라우저에서 http://127.0.0.1:8787을 엽니다. 끄는 건 실행한 터미널에서 Ctrl+C.

각자 자기 PC에서 자기 계정으로 돌립니다. 서버는 실행한 PC에서만 열리고, 계정 정보를 다른 곳으로 복사하는 단계는 없습니다.

C · 한국어 미러

에이전트의 영어를 한국어로 보기

B의 채팅 설치Gemini API 키
  1. 번역 키 넣기

    위키 저장소 폴더에 .env를 만들고 키를 적습니다. 기계 전역 환경변수보다 이 파일이 우선합니다. 키가 없으면 번역 없이 원문이 그대로 나옵니다.

    GEMINI_API_KEY=여기에-본인-키
  2. 미러 열기 
    tool\mirror.cmd        # Windows
tool/mirror.command    # macOS·Linux

    http://127.0.0.1:8787/#mirror가 열립니다. 왼쪽엔 대화가 한국어로, 오른쪽엔 실제 명령과 패치가 번역 없이 쌓입니다. 번역한 명령은 더 이상 실행되는 명령이 아니니까요.

  3. 다른 작업트리 보기

    화면 위쪽 드롭다운에서 호스트(claude · codex)와 작업트리를 고릅니다. 한 저장소의 작업트리는 그 저장소 아래에 묶여 있습니다.

  4. 화면 없이 터미널로만 
    python tool/mirror.py --project .
python tool/mirror.py --host codex --project C:\path\to\other-repo

한 저장소에 작업 셀이 둘 이상이면 “가장 최근 세션”이 계속 바뀝니다. 그때는 --session <세션 파일>로 따라갈 파일을 직접 지정하세요.

하루를 돌아보고 고치기

규칙은 저절로 생기지 않아요. 하루를 마칠 때 앱의 회고 포커스가 오늘 어긋난 자리를 세어 규칙 후보로 내고, 사람이 그중 무엇을 남길지 골라요. 고른 건 다른 작업과 똑같이 명세 → 리뷰 → 머지를 거쳐 규칙이 돼요.

이걸로 푸는 문제같은 걸 몇 번이나 바로잡았는지는 그날이 지나면 잊혀요. 기억에 의존하면 크게 데인 것만 남고, 매일 조금씩 새는 것은 끝까지 규칙이 되지 못해요.
회고

한 일을 늘어놓지 않고, 어긋난 걸 세요

  1. 오늘의 재료그 저장소의 오늘 커밋과 대화 기록이에요. 기록 전체가 아니라 사람이 한 말과 도구 횟수만 뽑아요
  2. 세기정정한 횟수, 같은 지시를 반복한 횟수, 하다 만 일, 뒤집은 결정을 세요
  3. 후보 줄줄마다 분류 · 횟수 · 지킬 규칙 · 관련 페이지가 붙어요. 이미 있는 규칙을 또 어겼다면 글을 늘리지 않고 지키게 하는 칸을 한 칸 올리자고 해요
  4. 사람이 고르기줄마다 버튼 셋 중 하나를 눌러요
  5. 다음 작업으로명세가 되어 [시작] · 리뷰 · 머지를 거쳐요. 머지되면 다음 세션부터 훅이 그 규칙을 읽혀요
버튼누르면
위키로규칙 페이지 하나를 만드는 명세 요청이 다음 작업 입력칸에 들어가요. 이미 있는 규칙이면 지키게 하는 칸을 올리는 요청이 돼요
CLAUDE.md로그 저장소의 CLAUDE.md에 한 문장을 넣는 명세 요청이 들어가요
버린다아무것도 남기지 않아요

회고는 파일을 직접 고치지 않아요. 후보만 내고, 무엇이 규칙이 될지는 사람이 정해요. 원인을 캐는 일이라 기본 추론 강도를 높게 잡아 둬요. “지키게 하는 칸”이 무엇인지는 ① 규칙 훅의 다섯 칸에 있어요.

자가 개선

고친 게 정말 나아졌는지는 재고 나서 골라요

회고가 사람이 도는 고리라면, 자가 개선은 측정으로 도는 고리예요. 대화 중에 저절로 돌지 않아요. 사람이 실험 설정을 주고 tool/improve.py로 직접 돌려요. 대상은 이 저장소(공통 규칙과 도구) 또는 연결한 저장소 하나예요.

  1. 실험 조건 고정하기실험 내용, 쓸 모델, 평가 명령, 과제, 전체 예산을 정해요. 바꾸면 새 실험이에요
  2. 지금 상태 재기따로 꺼낸 작업 폴더에서 지금 코드를 평가해요
  3. 고칠 안 여러 개지금 코드에서 출발한 독립된 수정안을 여러 개 만들어요
  4. 평가 전에 거르기건드리면 안 되는 곳을 건드렸는지, 답을 흘렸는지, 채점을 속였는지 따로 검사해요
  5. 재고 고르기잡음 범위를 넘어 나아진 안만 골라요. 없으면 지금 코드를 지켜요
  6. 처음 보는 과제로 확인수정안을 고를 때 쓰지 않은 과제로 마지막에 한 번 비교해요. 통과해도 리뷰와 게이트는 거쳐요

비용을 모르면 멈춰요. 0으로 치지 않아요. 실험 기록은 로컬의 raw/improvement/에만 남고, 공유하는 지식에는 들어가지 않아요. 연결한 저장소에서 나온 개선이 공통 규칙이 되려면 따로 제안하고 다른 곳에서도 통한다는 걸 보여야 해요.

리팩터링 실행기도 같은 장치를 써요. 수정안을 서로 겨루게 하고, 얼려 둔 동작 테스트와 래칫이 거르는 역할을 해요.

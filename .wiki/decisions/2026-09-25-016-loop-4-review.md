# feat: loop stage 4 — The PR goes through the review loop until it is mergeable, is tied to the head allowed by [merge], and is merged and cleaned up

What. Loop stage 4. A single PR goes through review rounds without human intervention until `머지 가능`. The only places waiting for a human are write approval and [merge]. Review cell: One read-only session per PR (Codex base model · effort `high`, Claude `Read,Glob,Grep`). The round file is in the hub's `raw/review/<repo>/<pr>/` loop: round parser, one thread per loop, concurrent execution limit, stop reasons are the enum as shown in the plan table. …

Why. The round file is placed in the hub, not the `review_dir` of the working tree — the `git add -A` of the working cell can commit, and if the working tree is deleted, the record also disappears (discarded: `review_dir`) Do not use `READ_TOOLS` in the Claude review cell — the `Bash` there runs without approval and uses one `python -c`. Prompts cannot prevent writing (discarded: blocking with prompts) Merge is tied to the head allowed by the review, not the head seen on the screen — if it is pushed after approval and the list is read again, the head on the screen becomes a commit that has not been reviewed. Do not treat the exit code of `gh pr merge` as a merge — in the merge queue, it only adds to the queue or turns on auto-merge. …

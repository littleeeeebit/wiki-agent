# Refactoring 6/6: Open hub scope as linked worktree

What. This is step 6 of the refactoring series. It opens the wiki-agent itself (the hub) to be refactored. As per the owner's decision, only the functionality was created, and the actual application to the hub code was excluded.

Why. Hub execution creates its own linked worktree in `worktree_home(repo)/<명세 id>` at each step (including property tests). The checkout of the currently running server does not change its branch or HEAD. Since the hub specification does not have `workspace_mode`, merge cleanup removes each worktree. - The runner runs in that worktree, and the gate uses the one from the original checkout (`prepare(gate=...)`). This is because the adapter that wrote the gate is a machine-specific configuration that Git does not move. - Hub's foreground mode is blocked. This is because the planner branches the server checkout. The tab notifies that the merged hub step requires an app restart to be reflected. …

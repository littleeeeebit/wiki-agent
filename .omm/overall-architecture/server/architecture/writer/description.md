architecture.write_nodes validates the complete path hierarchy and every described diagram child before publication. It rejects symlinks, escaped paths and reserved Mermaid node IDs, seeds a temporary OMM tree from existing documents and native metadata, then runs individual omm writes for changed fields. Owned obsolete descriptions and diagrams are pruned in staging; metadata-only obsolete elements use native omm delete. Because native deletion does not fix parent registries, the writer reconciles children from retained staged directories. Maintainer-only elements remain. After validation, it compares live document content, native metadata and tree membership with the original staging snapshot. Detected concurrent changes abort before publication or pruning, preserving the newer notes, history and registry; failures require an explicit retry, not another automatic paid scan. The check is not a cross-process transaction. Successful publication includes native history and changed generated fields, but never republishes existing maintainer fields or binary assets. Temporary CLI Git provenance points at the actual repository. Unchanged fields keep their metadata. .omm/analysis.json records generated ownership; obsolete empty owned elements are removed locally only after staged validation. Invalid analysis leaves the previous architecture intact.
